# Alert Engine & Strategy Logic Chains

The TenX alert engine is a financial-grade event processing system capable of evaluating stateful price level crossings, candlestick formations, technical indicator states, and multi-stage conditional strategy chains.

---

## 1. Alert Types & Taxonomy

TenX categorizes alerts into four primary types:

| Alert Type (`AlertType`) | Description | Primary Attributes |
| :--- | :--- | :--- |
| **`priceLevel`** | Single boundary crossing on price action. | `targetPrice`, `condition`, `previousPrice` |
| **`candlestickPattern`** | Confirmation of a 1-to-3 bar Japanese candlestick formation. | `candlestickPattern`, `timeframe`, `triggerOnCandleClose` |
| **`technicalIndicator`** | Threshold crosses, signal line crosses, or flips on indicators. | `indicatorConfig` (`rsi`, `macd`, `maCross`, `bollingerBands`, `stochastic`, `supertrend`) |
| **`multiStepChain`** | Ordered sequence of multi-condition stages requiring sequential satisfaction. | `multiStepConfig` (`stages`, `timeoutMinutes`, `currentStageIndex`) |

---

## 2. Stateful Boundary Crossing Logic

### The "Instant False Positive" Flaw in Naive Alert Systems
Naive alert engines simply evaluate static inequalities on every incoming tick:
$$\text{isTriggered} = P_{curr} \ge Target$$
This causes severe operational errors:
1. If an alert is created when the market is already above the target, it fires immediately on the very first tick.
2. If multi-symbol cloning copies EUR/USD (~1.08) into USD/JPY (~155) or Gold (~2650), the alert immediately screams false alarms.

### TenX Stateful Boundary Crossing Algorithm
TenX enforces strict directional transition across the boundary threshold:

$$\text{Baseline} = P_{prev} \neq \text{null} \ ?\ P_{prev} : P_{initial}$$

* **Crosses Above:**
  $$\text{Trigger} \iff \text{Baseline} < Target \quad \land \quad P_{curr} \ge Target$$
* **Crosses Below:**
  $$\text{Trigger} \iff \text{Baseline} > Target \quad \land \quad P_{curr} \le Target$$
* **Hits Price:**
  $$\text{Trigger} \iff |P_{curr} - Target| \le (Target \times 0.0002) \quad (\pm 2 \text{ bps tolerance})$$

### Continuous State Tracking Through Cooldown
To ensure the engine maintains continuous awareness of market trajectory, $P_{prev}$ is updated to $P_{curr}$ on **every incoming tick**, even during active cooldown deadbands. When cooldown expires, the engine knows whether price has dipped below the boundary and completed a true re-crossing.

Implementation in [market_models.dart](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/lib/models/market_models.dart#L856-L879):
```dart
bool checkTrigger(double currentPrice, {DateTime? now}) {
  if (!isActive || isPatternAlert || isIndicatorAlert || isMultiStepAlert) return false;
  final currentTime = now ?? DateTime.now();
  final baseline = previousPrice ?? initialPrice;
  previousPrice = currentPrice;

  // Cooldown Hysteresis Filter
  if (cooldownMinutes > 0 && lastTriggeredAt != null) {
    if (currentTime.difference(lastTriggeredAt!).inMinutes < cooldownMinutes) {
      return false; // Still within cooldown deadband
    }
  }

  bool isTriggered = false;
  switch (condition) {
    case AlertCondition.crossesAbove:
      isTriggered = baseline < targetPrice && currentPrice >= targetPrice;
      break;
    case AlertCondition.crossesBelow:
      isTriggered = baseline > targetPrice && currentPrice <= targetPrice;
      break;
    case AlertCondition.hits:
      isTriggered = (currentPrice - targetPrice).abs() <= (targetPrice * 0.0002);
      break;
  }
  return isTriggered;
}
```

## 3. Rearm Hysteresis & Cooldown

To prevent "alarm chatter" (rapid repeated alarms when price oscillates around a boundary in high-volatility conditions), TenX alerts support customizable cooldown deadbands:
* **`cooldownMinutes = 0` (Single Shot):** The alert rings once and immediately transitions to `isActive = false`.
* **`cooldownMinutes > 0` (Rearmable):** The alert rings, records `lastTriggeredAt = now`, and remains `isActive = true`. For the duration of `cooldownMinutes`, further alarms are suppressed. Once the window expires, the alert re-arms and requires a fresh boundary crossing to fire again.

---

## 4. Multi-Step Logic Chains & Expiry Windows

Multi-step logic chains allow traders to define complex trade setup sequences (e.g., *Breakout Level 1 $\rightarrow$ Pullback to Support $\rightarrow$ Bullish Hammer Confirmation*).

```mermaid
stateDiagram-v2
    [*] --> Stage1: Alert Created
    Stage1 --> Stage2: Stage 1 Satisfied (CompletedAt recorded)
    Stage2 --> Stage1: Timeout Expired (Auto-Reset)
    Stage2 --> Stage3: Stage 2 Satisfied (CompletedAt recorded)
    Stage3 --> Stage1: Timeout Expired (Auto-Reset)
    Stage3 --> Triggered: All Stages Satisfied!
    Triggered --> [*]: Alarm Fired & Logged
```

### Chain Structure & Logic Operators
* **`ChainStage`:** Contains a collection of `ChainNode` items connected via `logicOperator` (`AND` / `OR`).
* **`ChainNode`:** Can evaluate a price level, a candlestick pattern, or a technical indicator. Supports `isNegated = true` (NOT operator) to invert the condition.
* **Stage Timeout (`timeoutMinutes`):** Defines the maximum allowed time between the completion of Stage $N$ and Stage $N+1$. If the market does not fulfill Stage $N+1$ within this window, the entire chain automatically invalidates and resets back to Stage 1.
* **Timeout Override (`timeoutMinutes = 0`):** Explicitly disables stage timeout, allowing the stage to wait indefinitely without expiring.

### Live UI Countdown Badge
The UI dynamically computes the remaining duration via `MultiStepConfig.timeRemaining(DateTime now)`:
```dart
Duration? timeRemaining(DateTime now) {
  if (currentStageIndex == 0) return null;
  final prev = previousStage;
  if (prev == null || prev.completedAt == null) return null;

  final limit = prev.timeoutMinutes > 0 ? prev.timeoutMinutes : timeoutMinutes;
  if (limit <= 0) return null;

  final elapsed = now.difference(prev.completedAt!);
  final totalDuration = Duration(minutes: limit);
  if (elapsed >= totalDuration) return Duration.zero;
  return totalDuration - elapsed;
}
```
In [alerts_list_sheet.dart](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/lib/screens/alerts_list_sheet.dart#L1215-L1228), this renders as an active countdown badge:
$$\text{"⏳ 14m 32s left"}$$

---

## 5. Multi-Symbol Strategy Deployment

Traders can deploy a multi-step chain across multiple instruments simultaneously with a single tap. To ensure price isolation:
1. `AlertManager.createMultiSymbolAlerts` receives `symbolPrices: Map<String, double>`.
2. Each target instrument receives its own deeply cloned `MultiStepConfig` with symbol-prefixed stage IDs (`stg_EURUSD_...`, `stg_GBPUSD_...`).
3. Each clone is initialized with the genuine live price of its specific currency, preventing EUR/USD prices from corrupting USD/JPY or Gold levels.

---

## 6. Drawing-Attached Chart Alerts

When drawing technical structures on the interactive candlestick chart (horizontal support/resistance lines, trendlines, or rays):
* Users can tap the alert bell on any active drawing to attach a price alert directly to that geometric object (`drawingId`).
* When the user adjusts the drawing handles on the chart, `onScaleEnd` captures the updated coordinate and immediately synchronizes the alert target price in `AlertManager` and `DrawingStorageService`.

## 2. Notification Channel Architecture & ID Segregation

Android Oreo (API 26+) requires explicit notification channels. To prevent heads-up alarm popups from colliding with or dismissing the perpetual service, TenX maintains two independent channels:

### Channel 1: Persistent Service Channel (`CHANNEL_ID = "ForexMarketServiceChannel"`)
* **Importance:** `IMPORTANCE_LOW` (silent, non-intrusive).
* **Notification ID:** `1001` (Fixed).
* **Behavior:** Ongoing notification indicating real-time background market tracking is active. Cannot be swiped away by the user.

### Channel 2: High-Priority Price Alarms (`ALARM_CHANNEL_ID = "ForexPriceAlarmChannel"`)
* **Importance:** `IMPORTANCE_HIGH` (maximum visibility).
* **Notification ID Range:** `ALARM_NOTIFICATION_BASE_ID = 2000 + Math.abs(title.hashCode() % 1000)`.
* **Behavior:** Renders as a full heads-up notification card with action button `DISMISS ALARM`, overrides Do Not Disturb, and wakes the device screen.
* **Segregation Benefit:** By isolating alarm notifications to IDs $\ge 2000$, dismissing or clearing an alarm notification never terminates or replaces the persistent service notification `1001`.

---

## 3. Power Management & Doze Mode WakeLocks

When a device is left unattended, Android transitions into aggressive power-saving Doze modes. TenX maintains active status through:

1. **Partial WakeLock:**
   ```kotlin
   wakeLock = powerManager.newWakeLock(
       PowerManager.PARTIAL_WAKE_LOCK,
       "AlertApp:PerpetualForegroundWakeLock"
   ).apply {
       setReferenceCounted(false)
       acquire()
   }
   ```
   Keeps the device CPU running at baseline frequency while allowing the display to remain completely off, ensuring minimal battery consumption.
2. **Foreground Service Declaration:** Declared with Android 14+ compliant foreground service types (`dataSync`) in `AndroidManifest.xml`.
3. **Screen Wakeup on Alarm:** When an alert fires, `AlarmPlayer.kt` temporarily acquires a full screen wakeup lock (`FLAG_KEEP_SCREEN_ON | FLAG_TURN_SCREEN_ON | FLAG_SHOW_WHEN_LOCKED`) to present the alarm interface directly on the lockscreen.

## 4. Audio Playback & Do Not Disturb (DND) Bypass

Standard media audio streams (`STREAM_MUSIC`) are muted when the device is set to Do Not Disturb or Vibrate. TenX routes emergency price alarms through the Android Alarm Audio Stream:

Implementation in [AlarmPlayer.kt](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/android/app/src/main/kotlin/com/example/alert_app/AlarmPlayer.kt):
```kotlin
val audioAttributes = AudioAttributes.Builder()
    .setUsage(AudioAttributes.USAGE_ALARM)
    .setContentType(AudioAttributes.CONTENT_TYPE_SONIFICATION)
    .build()

mediaPlayer?.apply {
    setAudioAttributes(audioAttributes)
    isLooping = looping
    start()
}
```
* **DND Bypass:** Android OS prioritizes `USAGE_ALARM` above all media rules, ensuring price alerts ring loudly even during active Do Not Disturb schedules.
* **Vibrator Pattern:** Synchronized dual-burst haptic feedback (`[0, 500, 200, 500] ms`) accompanies the audio playback.

---

## 5. In-Memory OHLC Pre-Caching

Evaluating technical indicators (e.g. 200-period EMA, Bollinger Bands, Stochastic) and candlestick patterns for multiple background alerts requires historical candle data. To eliminate serial network blocking:
* `fetchOhlcBars(symbol, timeframe, limit)` maintains a thread-safe `ConcurrentHashMap<String, Pair<Long, JSONArray>>` cache.
* **TTL:** 10 seconds.
* **Pre-Caching Step:** At the start of each polling loop, all active alerts and multi-step stages are scanned to extract distinct `(symbol, timeframe)` pairs, fetching required bars concurrently before sequential rule evaluation.

---

## 6. Self-Healing & Boot Persistence

Aggressive OEM battery management solutions (e.g., Xiaomi MIUI, Samsung OneUI, OnePlus OxygenOS) may attempt to kill background processes. TenX incorporates dual self-healing mechanisms:

1. **`BootAndAlarmReceiver.kt`:**
   * Listens for `android.intent.action.BOOT_COMPLETED`, `android.intent.action.LOCKED_BOOT_COMPLETED`, and `android.intent.action.QUICKBOOT_POWERON`.
   * Automatically invokes `startForegroundService` immediately upon phone boot without requiring the user to manually open the app.
2. **`AlarmWatchdog.kt`:**
   * Registers a repeating exact alarm with `AlarmManager.setExactAndAllowWhileIdle()`.
   * Periodically verifies that `AlertForegroundService` is actively running; if the process was killed, the watchdog restarts the service.

# System Architecture & High-Level Design

The **TenX Institutional Trading Terminal** is built on a high-reliability, zero-synthetic financial architecture designed for professional Forex, Metals, Cryptocurrencies, and Index CFD traders. It combines an ultra-fast Flutter client for interactive charting and AI analysis with a perpetual, native Android daemon that guarantees continuous 24/7 background market monitoring even when the application is swiped away or the device screen is locked.

---

## 1. Core Architectural Principles

1. **Zero Synthetic / Mock Math:** Unlike consumer retail apps that generate random walk price ticks or synthetic pips when disconnected, TenX enforces complete data integrity. When markets are closed for the weekend or network is lost, the terminal transitions transparently into greyscale standby mode without fabricating quotes.
2. **Dual-Runtime Execution Engine:**
   * **Foreground Runtime (Flutter / Dart):** Renders the custom canvas 60 FPS candlestick charts, manages UI navigation, handles user interactions, runs interactive technical drawing tools, and coordinates multi-agent LLM strategy executions.
   * **Background Runtime (Android Native / Kotlin):** A decoupled background process running inside `AlertForegroundService.kt`. Operates independently with a CPU partial wakelock, evaluating multi-step logic chains, technical indicator formulas, and candlestick patterns directly against Biquote HTTP endpoints without Flutter VM overhead.
3. **Stateful Parity:** Mathematical indicator algorithms (Wilder's RMA, EMA smoothing, Supertrend trailing stop flips, MACD, Bollinger Bands) and alert conditions maintain strict 1:1 mathematical parity between Dart and Kotlin.

## 4. Bi-Directional State Synchronization

Storage synchronization between Flutter and Android is maintained via SharedPreferences:

| Preference Key | Type | Description |
| :--- | :--- | :--- |
| `saved_alerts` / `flutter.saved_alerts` | JSON Array | Active alert configurations including multi-step stages, completion timestamps, and `previousPrice` baselines. |
| `saved_history` / `flutter.saved_history` | JSON Array | Triggered alert audit logs with trigger price, timestamp, and symbol. |
| `KEY_ACTIVE_ALERTS` | JSON Array | Internal cache utilized by `AlertForegroundService` during polling cycles. |

When either runtime modifies an alert:
1. In Flutter: `AlertManager.saveAlerts()` serializes the alerts to JSON, updates SharedPreferences, and calls MethodChannel `syncAlerts` to immediately alert the native service.
2. In Android: `AlertForegroundService.syncToFlutterStorage()` modifies the JSON representation, persists it back to SharedPreferences with `commit()`, ensuring that when the user switches back to the Flutter app, state is seamlessly in sync.

# Charting & Interactive Drawing Engine

The TenX charting engine provides high-fidelity, interactive technical analysis rendering directly on Flutter's hardware-accelerated canvas via `CustomPainter`. It delivers TradingView-class touch ergonomics, sub-pixel rendering precision, and drawing-attached alerting.

---

## 1. Coordinate Transformation System

The candlestick canvas maps non-linear financial time-series data into 2D screen coordinates:

$$\text{Canvas Width} = W, \quad \text{Canvas Height} = H$$
$$\text{Price Scale} = \frac{H - \text{padding}}{\text{MaxPrice} - \text{MinPrice}}$$

* **X Coordinate Mapping:** Determined by the visible candle index, the horizontal pan offset (`_panOffset`), and the dynamic candle width (`_candleWidth`):
  $$X_i = W - \text{PriceAxisWidth} - ((N - 1 - i) \times \text{CandleWidth}) + \text{PanOffset}$$
* **Y Coordinate Mapping:** Inverts financial price space to canvas space (where $Y=0$ is the top edge):
  $$Y(P) = ( \text{MaxPrice} - P ) \times \text{PriceScale} + \text{TopPadding}$$

---

## 1. Currency Cross Matrix Heatmap

### Relative Strength Math
For each currency $C_i$, the net strength score $S(C_i)$ is computed by aggregating performance against all 7 counterparts:
$$S(C_i) = \sum_{j \neq i} \Delta\%(C_i / C_j)$$

## 3. Strict JSON Extraction Protocol

LLMs frequently output conversational filler or preamble text around JSON blocks. TenX enforces resilient extraction via [ai_models.dart](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/lib/models/ai_models.dart#L125-L165):

```dart
static Map<String, dynamic> extractJson(String rawText) {
  final clean = rawText.trim();

  // 1. Try markdown code fences ```json ... ```
  final codeBlockRegex = RegExp(r'```(?:json)?\s*([\s\S]*?)\s*```', caseSensitive: false);
  final match = codeBlockRegex.firstMatch(clean);
  if (match != null) {
    final blockContent = match.group(1)?.trim();
    if (blockContent != null && blockContent.isNotEmpty) {
      try {
        return jsonDecode(blockContent) as Map<String, dynamic>;
      } catch (_) {}
    }
  }

  // 2. Scan for raw outer curly braces {...}
  final firstBrace = clean.indexOf('{');
  final lastBrace = clean.lastIndexOf('}');
  if (firstBrace != -1 && lastBrace != -1 && lastBrace > firstBrace) {
    final substring = clean.substring(firstBrace, lastBrace + 1);
    try {
      return jsonDecode(substring) as Map<String, dynamic>;
    } catch (_) {}
  }

  throw const FormatException('No valid JSON structure found in LLM response');
}
```

## 3. Resilience Engineering: Direct IP Fallback

In mobile environments, Android emulators, and restrictive mobile ISP networks, DNS lookups for newly provisioned fintech domains may fail or be poisoned. TenX implements dual-route resilience:

1. **Route 1 (Standard):** Dispatches standard HTTPS/WSS requests to `biquote.io` with a strict 3-second timeout.
2. **Route 2 (Direct IP Bypass):** If Route 1 throws `SocketException` or times out, the engine executes an immediate fallback to `142.132.248.240`, injecting `Host: biquote.io` and configuring `badCertificateCallback = (cert, host, port) => true`.

Implementation in [biquote_service.dart](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/lib/services/biquote_service.dart#L61-L88):
```dart
Future<dynamic> _fetchJson(String pathAndQuery) async {
  // 1. Try primary domain first
  try {
    final uri = Uri.parse('$baseUrl$pathAndQuery');
    final response = await _client.get(uri).timeout(const Duration(seconds: 3));
    if (response.statusCode == 200) return jsonDecode(response.body);
  } catch (_) {}

  // 2. Resilient Direct IP Fallback with Host header injection
  try {
    final uri = Uri.parse('$directBaseUrl$pathAndQuery');
    final req = await _ioClient.getUrl(uri).timeout(const Duration(seconds: 4));
    req.headers.set('Host', 'biquote.io');
    final resp = await req.close().timeout(const Duration(seconds: 4));
    if (resp.statusCode == 200) {
      final body = await resp.transform(utf8.decoder).join();
      return jsonDecode(body);
    }
  } catch (_) {}

  return null;
}
```

# Technical Indicators & Candlestick Pattern Engine

TenX includes a high-performance quantitative calculation engine implemented with strict 1:1 parity between Flutter Dart ([indicator_calculator.dart](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/lib/services/indicator_calculator.dart)) and Android Kotlin ([AlertForegroundService.kt](file:///c:/Users/hp/Documents/Web-Projects/Alert-App/android/app/src/main/kotlin/com/example/alert_app/AlertForegroundService.kt)).

---

## 1. Technical Indicators Mathematical Specification

### A. Relative Strength Index (RSI)
RSI measures momentum by comparing the magnitude of recent gains to recent losses over period $N$ (default $N=14$).

1. **Price Changes:**
   $$\Delta P_t = P_t - P_{t-1}, \quad U_t = \max(\Delta P_t, 0), \quad D_t = \max(-\Delta P_t, 0)$$
2. **Smoothing:**
   * **Wilder's RMA (Default):**
     $$\overline{U}_t = \frac{\overline{U}_{t-1} \times (N - 1) + U_t}{N}, \quad \overline{D}_t = \frac{\overline{D}_{t-1} \times (N - 1) + D_t}{N}$$
   * **EMA:**
     $$\alpha = \frac{2}{N + 1}, \quad \overline{U}_t = (U_t \times \alpha) + (\overline{U}_{t-1} \times (1 - \alpha))$$
3. **Index Calculation:**
   $$RS = \frac{\overline{U}_t}{\overline{D}_t}, \quad RSI = 100 - \left( \frac{100}{1 + RS} \right)$$
* **Conditions Supported:** `crossesAboveLevel`, `crossesBelowLevel`, `crossesAboveOversold` (<30), `crossesBelowOverbought` (>70), `crossesAboveCenterline` (50), `crossesBelowCenterline` (50), `rsiTurningUp` (momentum hook), `rsiTurningDown`, `crossesAboveSignalMa`, `crossesBelowSignalMa`.

---

### B. Moving Average Convergence Divergence (MACD)
Standard MACD parameters: Fast $= 12$, Slow $= 26$, Signal $= 9$.

1. **MACD Line:**
   $$MACD_t = EMA_{Fast}(P) - EMA_{Slow}(P)$$
2. **Signal Line:**
   $$Signal_t = EMA_{Signal}(MACD)$$
3. **Histogram:**
   $$Hist_t = MACD_t - Signal_t$$
* **Conditions Supported:** `bullishSignalCross` ($MACD > Signal$), `bearishSignalCross` ($MACD < Signal$), `zeroLineCrossAbove` ($MACD > 0$), `zeroLineCrossBelow` ($MACD < 0$), `histogramFlipPositive`, `histogramFlipNegative`, `histogramTurningUp`, `histogramTurningDown`.

---

### C. Moving Averages & MA Crossover
Supports EMA, SMA, and WMA across user-defined periods (e.g. 50/200 Golden Cross).

* **Simple Moving Average (SMA):**
  $$SMA_t = \frac{1}{N} \sum_{i=0}^{N-1} P_{t-i}$$
* **Exponential Moving Average (EMA):**
  $$\alpha = \frac{2}{N+1}, \quad EMA_t = (P_t \times \alpha) + (EMA_{t-1} \times (1 - \alpha))$$
* **Weighted Moving Average (WMA):**
  $$WMA_t = \frac{\sum_{i=0}^{N-1} (N - i) P_{t-i}}{\frac{N(N+1)}{2}}$$
* **Conditions Supported:** `goldenCross` ($Fast > Slow$), `deathCross` ($Fast < Slow$), `priceCrossesAboveFast`, `priceCrossesBelowFast`, `priceCrossesAboveSlow`, `priceCrossesBelowSlow`, `priceAboveBoth`, `priceBelowBoth`, `priceBetweenMAs`.

---

### D. Bollinger Bands
Parameters: Period $N = 20$, Standard Deviation Multiplier $K = 2.0$.

1. **Middle Band:** $Middle_t = SMA_N(P)$
2. **Standard Deviation:**
   $$\sigma_t = \sqrt{\frac{1}{N} \sum_{i=0}^{N-1} (P_{t-i} - Middle_t)^2}$$
3. **Upper & Lower Bands:**
   $$Upper_t = Middle_t + (K \times \sigma_t), \quad Lower_t = Middle_t - (K \times \sigma_t)$$
4. **Bandwidth & %B:**
   $$Bandwidth_t = \frac{Upper_t - Lower_t}{Middle_t}, \quad \%B_t = \frac{P_t - Lower_t}{Upper_t - Lower_t}$$
* **Conditions Supported:** `priceCrossesAboveUpper`, `priceCrossesBelowUpper`, `priceCrossesBelowLower`, `priceCrossesAboveLower`, `middleBandCrossAbove`, `middleBandCrossBelow`, `squeeze` ($BW \le 0.015$), `squeezeBreakout` ($BW_{prev} \le Threshold \land BW_{curr} > Threshold$), `percentBCrossesAbove80`, `percentBCrossesBelow20`.

---

### E. Stochastic Oscillator
Parameters: $\%K = 14$, $\%K\text{ Slowing} = 3$, $\%D = 3$.

1. **Raw Stochastic:**
   $$Fast\%K = \frac{Close_t - \min(Low_{t-13..t})}{\max(High_{t-13..t}) - \min(Low_{t-13..t})} \times 100$$
2. **Full $\%K$:** $SMA_{Slowing}(Fast\%K)$
3. **Signal $\%D$:** $SMA_D(\%K)$
* **Conditions Supported:** `bullishCross` ($\%K > \%D$), `bearishCross` ($\%K < \%D$), `bullishOversoldCross` ($\%K > \%D \land \%K \le 20$), `bearishOverboughtCross` ($\%K < \%D \land \%K \ge 80$), `kCrossesAbove50`, `kCrossesBelow50`.

---

### F. Supertrend
Parameters: Period $N = 10$, Multiplier $M = 3.0$, ATR Smoothing: Wilder RMA.

1. **True Range (TR):**
   $$TR_t = \max(High_t - Low_t, |High_t - Close_{t-1}|, |Low_t - Close_{t-1}|)$$
2. **Average True Range (ATR):** $ATR_t = RMA_N(TR)$
3. **Basic Bands:**
   $$BasicUpper_t = \frac{High_t + Low_t}{2} + (M \times ATR_t), \quad BasicLower_t = \frac{High_t + Low_t}{2} - (M \times ATR_t)$$
4. **Final Bands & Ratcheting Logic:**
   $$FinalUpper_t = (BasicUpper_t < FinalUpper_{t-1} \lor Close_{t-1} > FinalUpper_{t-1}) \ ?\ BasicUpper_t : FinalUpper_{t-1}$$
   $$FinalLower_t = (BasicLower_t > FinalLower_{t-1} \lor Close_{t-1} < FinalLower_{t-1}) \ ?\ BasicLower_t : FinalLower_{t-1}$$
5. **Trend Flip:**
   $$Trend_t = \begin{cases} +1 & \text{if } Close_t > FinalUpper_{t-1} \\ -1 & \text{if } Close_t < FinalLower_{t-1} \\ Trend_{t-1} & \text{otherwise} \end{cases}$$
* **Conditions Supported:** `bullishFlip` ($Trend_{prev} = -1 \land Trend_{curr} = 1$), `bearishFlip` ($Trend_{prev} = 1 \land Trend_{curr} = -1$), `priceCrossesAboveTrail`, `priceCrossesBelowTrail`, `priceBouncesOffTrail`, `priceDistanceGreaterThan`.

## 1. Automated Test Suite

TenX maintains automated test suites covering all mathematical indicators, boundary crossing rules, multi-step chain logic, and LLM extraction protocols.

### Test Execution Commands
```bash
# Run all project tests
flutter test

# Run individual test files
flutter test test/engine_fixes_test.dart
flutter test test/ai_pipeline_test.dart
flutter test test/widget_test.dart
```

### Coverage Breakdown

#### A. Alert Engine & Mathematical Fixes (`test/engine_fixes_test.dart`)
1. **Candlestick Pattern Timing:** Confirms open forming bar (`isOpen: true`) is ignored and pattern matching evaluates confirmed closed bars (`isOpen: false`).
2. **Step Timeout & Auto-Reset:** Confirms that if a stage exceeds `timeoutMinutes`, `config.isTimedOut(now)` returns `true` and `config.reset()` restores Stage 1.
3. **Stage Remaining Duration:** Confirms `config.timeRemaining(now)` returns exact remaining minutes and seconds, returning `Duration.zero` once expired.
4. **False-Positive Prevention:** Confirms an alert created when price is already above target ($P_{initial} = 1.1550, Target = 1.1500$) does **not** trigger on the first tick; requires price to dip below $1.1500$ and cross upward.
5. **Hysteresis Cooldown & Re-Crossing:** Verifies alerts in cooldown suppress triggers, track $P_{prev}$ accurately on every tick, and only re-fire when cooldown expires and a fresh boundary transition occurs.
6. **Multi-Currency Price Isolation:** Verifies `createMultiSymbolAlerts` assigns genuine market prices per symbol (e.g. EURUSD: 1.0850, USDJPY: 155.30, XAUUSD: 2650.00) and clones independent stage trees.
7. **JSON Persistence Serialization:** Validates bi-directional serialization of nested multi-step stages, node operators (`OR`/`AND`), negations, and timestamps.

#### B. Multi-Agent AI & Indicator Logic (`test/ai_pipeline_test.dart`)
1. **TradingStrategy Serialization:** Verifies default agent prompts and timeframe arrays.
2. **AgentSignal JSON Extraction:** Validates regex parsing of Markdown code blocks (` ```json ... ``` `) and raw JSON strings.
3. **RealMarket Symbol & Timeframe Normalization:** Tests canonical code mapping (e.g. `GOLD` $\rightarrow$ `XAUUSD`, `15m` $\rightarrow$ `M15`).
4. **RSI Bounded Calculations:** Tests Wilder RMA smoothing and confirms RSI outputs remain bounded between 0 and 100.
5. **Pattern Detector Geometry:** Tests Bullish and Bearish Engulfing detection logic.

#### C. App Smoke Test (`test/widget_test.dart`)
1. **App Launch Smoke Test:** Verifies `TenXApp` mounts successfully without widget tree exceptions.
